# Installable, offline and phone-friendly — Design

**Date:** 2026-09-30
**Status:** Approved section by section in chat (offline & install, mobile layout, wake lock & testing).
**Builds on:** `2026-09-26-harmonica-tools-design.md` and `2026-09-27-more-tools-and-games-design.md`. Their architecture and conventions still apply, including the stable-layout rule, `useSpelling()`, and no per-frame re-renders on mic pages.

## 0. Goal and scope

**Goal:** someone practising with a phone on a music stand can:
- install Harp Tools;
- open it with no connection;
- see the whole harp in portrait;
- keep the screen on while they play.

**Done means:**
1. The app installs to the home screen (Android/desktop Chrome and Edge via the browser prompt; iOS via Share → Add to Home Screen) and opens with no connection after one online visit.
2. At 360 px wide, no page scrolls sideways, and all 10 holes of the chart are visible without swiping.
3. The screen doesn't sleep while the mic is open, the metronome runs, or the band plays.
4. A new deploy never reloads the page mid-session.

**Out of scope:**
- accounts, sync, push notifications, a native app;
- a wake-lock setting;
- Playwright tests in CI (a separate follow-up).

## 1. Offline and install

**Tooling:** `vite-plugin-pwa` (Workbox `generateSW`) plus `workbox-window`. It supports Vite 8, and the plugin handles `base: './'`. A hand-written service worker was rejected because cache versioning and update edge cases are where these break. Manifest-only was rejected because it isn't offline.

**Precache:** everything in `dist/` (`**/*.{js,css,html,svg,png,webmanifest}`), about 400 KB. The app makes no runtime fetches, so every route works offline after the first visit. `getUserMedia` doesn't need the network. Hash routing means there is only one HTML entry, so no navigation fallback rules are needed.

**Update flow (`registerType: 'prompt'`):**
- The app registers through `useRegisterSW` from `virtual:pwa-register/react`.
- `UpdateBar` is fixed at the bottom of the screen and outside the page layout, so it never shifts page content (stable-layout rule). It shows one of two things:
  - **`needRefresh`:** "A new version is ready" with a **Reload** button (`updateServiceWorker(true)`) and a dismiss ✕. It never reloads automatically. If the user dismisses or ignores it, the waiting worker takes over on the next cold start.
  - **`offlineReady`:** "Ready to work offline" once, after the first install. It dismisses itself after 6 s or with ✕.
- It's mounted once in `App`, next to `<main>`.

**Manifest** (generated by the plugin):

| Field | Value |
|---|---|
| `name` / `short_name` | Harp Tools / Harp Tools |
| `description` | Practice tools and ear-training games for diatonic harmonica |
| `display` | `standalone` |
| `orientation` | `portrait` is **not** forced — landscape stays available |
| `start_url` / `scope` | `./` / `./` |
| `theme_color` / `background_color` | `#14161a` (current page background and `<meta name="theme-color">`) |
| `icons` | 192, 512, 512 maskable (PNG) |

**Icons:**
- One source `public/icon.svg`: a simple mark of harmonica holes in the accent colour on the dark background, with safe padding for masking.
- The PNGs (`pwa-192x192.png`, `pwa-512x512.png`, `maskable-icon-512x512.png`, `apple-touch-icon-180x180.png`, `favicon.ico`) are generated once with `@vite-pwa/assets-generator` (a dev dependency with the `minimal-2023` preset) and committed. There's an npm script `icons` to regenerate them.
- `index.html` gains the favicon and apple-touch-icon links.

**Install button:**
- `InstallButton` sits on the home page and listens for `beforeinstallprompt`. It prevents the default, keeps the event, and shows **Install app**.
- A click calls `prompt()`. The button hides after the choice, and also on `appinstalled`.
- It shows nothing when the app already runs standalone (`matchMedia('(display-mode: standalone)')`).
- On iOS Safari, which never fires the event, a one-line hint appears in the same place: "On iPhone or iPad: Share → Add to Home Screen". It's detected by user agent plus `!('onbeforeinstallprompt' in window)`, and hidden when standalone.

**Standalone polish:**
- `viewport-fit=cover` on the viewport meta.
- The header, `<main>` and `UpdateBar` pad with `env(safe-area-inset-*)`, so nothing sits under the notch or home bar.

## 2. Mobile layout

**Target:** 360 × 740 CSS px. The only element allowed to scroll sideways is the note-slot row.

### 2.1 Harmonica chart: compact mode

- `.wrap` gets `container-type: inline-size`. Compact rules apply under `@container (max-width: 34rem)`:
  - `.rowLabel` → `display: none` (the ~6 rem label column is the main waste). Technique is still carried by colour, the legend, and each cell's accessible name (`tabLabel` already includes it).
  - `.grid` → `grid-template-columns: repeat(10, minmax(0, 1fr))`, `gap: 3px`, `min-width: 0`. At 328 px, a column is about 30 px.
  - `.cell` → `font-size: 0.7rem`, `padding-inline: 0`, `min-height: 2.75rem` (44 px tap target in height).
  - `.cell[data-interactive]` → `touch-action: pan-y`. The chart no longer scrolls sideways, so a vertical swipe starting on a cell must scroll the page.
  - The hole-number row keeps its styling at a smaller size.
- **Octave subscript.** Note labels render as a pitch class plus a `<span className={styles.octave}>` with the octave digit. On wide screens it looks the same as today: same size, inline. In compact mode it's `font-size: 0.75em; vertical-align: sub`. Tab labels are unchanged. The accessible name is unchanged because `aria-label` is set explicitly.
- It's a container query, not a viewport query, so the chart also goes compact inside narrow panels on desktop.

### 2.2 Header: four rows to two

Under `@media (max-width: 30rem)`:
- Row 1: brand, then the Tuner / Metronome / Log links.
- Row 2: key · tuning selectors, then the GitHub star as an **icon-only** button. The "★ Star on GitHub" text is visually hidden but kept as the accessible name.
- Desktop is unchanged.

### 2.3 Health check table: transposed on narrow screens

- A new hook, `useMediaQuery(query): boolean`, uses `useSyncExternalStore` over `matchMedia`, following the `router.ts` pattern.
- Under `(max-width: 34rem)` the table renders transposed:
  - 10 rows (holes 1–10) × columns **Hole | Blow | Draw**;
  - the same cells, `data-quality` / `data-current` attributes and Δ line.
- Only one table is ever in the DOM.
- The `min-width: 34rem` on `.table` applies only to the wide layout.

### 2.4 Note slots (tab reader, licks)

- They keep `overflow-x: auto`, because long licks are meant to scroll.
- When the current slot changes and it's out of view, the row sets its own `scrollLeft` (the slot's `offsetLeft` minus an 8 px margin). `scrollIntoView` was rejected because it would also scroll the page vertically when the row is off-screen mid-run.

### 2.5 Small fixes

- Metronome page: fix the 2 px overflow at 360 px (its widest row).
- **Final sweep:** all 18 routes at 360 px, with audio unlocked. `document.documentElement.scrollWidth <= 360`, and nothing in `main` extends past the viewport except inside `.slots`.

## 3. Screen stays on

**Module:** `src/audio/screenAwake.ts`.

```ts
export interface WakeLockSentinelLike {
  release(): Promise<void>
  addEventListener(type: 'release', listener: () => void): void
}
export interface WakeLockApi { request(type: 'screen'): Promise<WakeLockSentinelLike> }
export class ScreenAwake {
  constructor(api?: WakeLockApi | undefined, doc?: Pick<Document, 'visibilityState' | 'addEventListener'>)
  /** Keep the screen on until the returned function is called (idempotent). */
  hold(): () => void
}
export const screenAwake: ScreenAwake // uses navigator.wakeLock when present
```

**Behaviour:**
- Holds are counted:
  - 0 → 1 requests the lock;
  - back to 0 releases it.
- On `visibilitychange` → `visible` with holds > 0 and no live sentinel, it requests again (browsers drop the lock when the tab is hidden). A sentinel's own `release` event clears it.
- Unsupported API, or a rejected request (battery saver, permissions policy): silently a no-op, with no message.
- A late-resolving request after the count has dropped to 0 is released immediately.

**Callers (audio layer, so new pages get it for free):**
- `Microphone`: hold while the stream is open. Released on stop, on the stream ending by itself, and on errors.
- `Metronome`: hold between `start()` and `stop()`.
- `BackingScheduler`: hold between `start()` and `stop()`/dispose.

The note quiz and positions pages use neither the mic nor audio, so the screen sleeps normally there.

## 4. Error handling

Everything degrades to today's behaviour:
- **Service worker unsupported, or registration fails:** the site works online only. There's no UI; the failure goes to `console.warn` via `onRegisterError`.
- **Precache fails** (quota, connection drops mid-install): Workbox retries on the next visit, with no UI.
- **Wake Lock missing or refused:** no-op (§3).
- **`beforeinstallprompt` never fires:** no button, plus the iOS hint where it applies.

## 5. Testing

**Unit and component (Vitest):**
- `ScreenAwake` with a fake API and document:
  - the count requests and releases once;
  - release is idempotent;
  - asks again on visible;
  - unsupported is a no-op;
  - a rejected request is swallowed;
  - a late resolve after release is released.
- `Microphone` / `Metronome` / `BackingScheduler`: hold on start and release on stop (inject a `ScreenAwake`).
- `UpdateBar`, with `virtual:pwa-register/react` aliased in the Vitest config to a controllable stub:
  - the offline-ready notice shows once and auto-hides;
  - needRefresh shows Reload → `updateServiceWorker(true)`;
  - ✕ hides it.
- `InstallButton`:
  - hidden by default;
  - a dispatched fake `beforeinstallprompt` shows it;
  - a click calls `prompt()` and hides it;
  - standalone → nothing;
  - the iOS branch shows the hint.
- `useMediaQuery`: follows a mocked `matchMedia` change.
- Health table: the transposed layout under a mocked narrow query, with Hole/Blow/Draw headers and 10 body rows.
- Note slots: a pure `scrollLeftToShow` helper, plus the row's `scrollLeft` following the current slot.
- Chart: note labels render the octave span; tab labels don't.

**Build check:** `scripts/check-pwa.ts`, run by an npm script `check:pwa` after `npm run build` and added to the deploy workflow. It asserts that `dist/sw.js` and `dist/manifest.webmanifest` exist, that manifest `start_url`, `scope` and icon `src` are relative, and that every icon file exists.

**Manual, by the agent (Playwright MCP):**
- the 360 px sweep (§2.5);
- reload with the network cut serves the app;
- the manifest and icons load without errors.

**Manual, by the user on devices:**
- install on Android and on iPhone;
- open in airplane mode;
- the screen stays on through a few minutes of tuner use;
- the update bar appears after a deploy.
